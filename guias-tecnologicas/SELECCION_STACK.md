# Selección de stack tecnológico

## Objetivo

Elegir tecnologías con criterios explícitos, comparables y trazables.

## Información previa obligatoria

- Problema y usuarios.
- Plataformas objetivo.
- Volumen esperado.
- Requisitos de seguridad y disponibilidad.
- Restricciones de presupuesto y plazo.
- Experiencia del equipo.
- Integraciones externas.
- Necesidad de funcionamiento offline.
- Estrategia de operación y mantenimiento.

## Matriz de evaluación

Puntuar cada alternativa de 1 a 5.

| Criterio | Peso | Alternativa A | Alternativa B | Alternativa C |
|---|---:|---:|---:|---:|
| Adecuación funcional | 20% | | | |
| Experiencia del equipo | 15% | | | |
| Mantenibilidad | 15% | | | |
| Seguridad | 10% | | | |
| Rendimiento y escalabilidad | 10% | | | |
| Ecosistema y soporte | 10% | | | |
| Coste total | 10% | | | |
| Velocidad de entrega | 5% | | | |
| Portabilidad | 5% | | | |

## Reglas

- No elegir por popularidad solamente.
- No introducir una tecnología nueva sin justificar su coste de aprendizaje.
- Separar necesidades actuales de posibilidades futuras.
- Validar supuestos críticos con una prueba de concepto.
- Registrar la decisión final y alternativas descartadas en un ADR.
- Definir versión mínima, política de actualización y responsable.

## Resultado esperado

- Stack elegido.
- Justificación.
- Riesgos y mitigaciones.
- Evidencia de prueba de concepto cuando corresponda.
- ADR aprobado.
