# Artefactos mínimos obligatorios

Todo proyecto debe conservar evidencia suficiente para explicar qué se construye, por qué, cómo se valida y cómo se mantiene.

## Inicio

- README con propósito, estado y ejecución.
- Brief del problema.
- Alcance y exclusiones.
- Usuarios y actores.

## Producto

- Requisitos priorizados.
- Criterios de aceptación.
- Flujos principales.
- Reglas de negocio.
- Requisitos no funcionales.

## Arquitectura

- Diagrama de contexto.
- Estructura principal del sistema.
- Registro de decisiones ADR.
- Dependencias e integraciones.
- Modelo de datos cuando aplique.
- Registro de riesgos.

## Ejecución

- Roadmap por fases.
- Objetivo y checklist de cada fase.
- Ramas y pull requests.
- Commits trazables.
- Estado actual del proyecto.

## Calidad

- Plan de pruebas proporcional al riesgo.
- Evidencia de pruebas.
- Defectos conocidos.
- Checklist de release.

## Entrega y operación

- Versionado y changelog.
- Instrucciones de despliegue.
- Estrategia de rollback.
- Variables y secretos documentados sin exponer valores.
- Guía de soporte y mantenimiento.

## Cierre

- Resultado frente al alcance.
- Deuda técnica pendiente.
- Lecciones aprendidas.
- Próximos pasos.

Un proyecto pequeño puede reunir varios artefactos en un solo documento. Lo importante es conservar el contenido y la trazabilidad, no multiplicar archivos sin necesidad.
