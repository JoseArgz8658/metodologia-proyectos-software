# Fase 3 — Metodología de desarrollo

## Objetivo

Definir un proceso reutilizable, trazable y adaptable para planificar, construir, validar, entregar y mantener proyectos de software.

La metodología debe funcionar como marco común para proyectos móviles, web, backend, escritorio, TV y soluciones con Firebase u otras plataformas.

## Principios

1. Cada proyecto comienza con un problema claramente definido.
2. Cada fase debe tener objetivo, alcance, entregables y criterios de aceptación.
3. Las decisiones importantes deben quedar documentadas.
4. El desarrollo debe avanzar en incrementos pequeños y comprobables.
5. `main` debe mantenerse estable.
6. Las pruebas y la documentación forman parte del trabajo, no son actividades opcionales al final.
7. El cierre de una fase requiere evidencia verificable.

## Ciclo de vida propuesto

1. Inicio y contexto.
2. Descubrimiento e investigación.
3. Levantamiento y priorización de requisitos.
4. Definición de alcance.
5. Arquitectura y decisiones técnicas.
6. Diseño UI/UX y prototipado.
7. Planificación por fases.
8. Preparación del repositorio y flujo Git.
9. Construcción incremental.
10. Pruebas y aseguramiento de calidad.
11. Despliegue y publicación.
12. Operación, mantenimiento y evolución.
13. Cierre y lecciones aprendidas.

## Documentación prevista

Durante esta fase se crearán guías específicas para:

- Inicio de proyecto.
- Investigación y descubrimiento.
- Requisitos y alcance.
- Arquitectura.
- UI/UX.
- Planificación por fases.
- Git Flow.
- Desarrollo.
- Testing.
- Despliegue.
- Mantenimiento.
- Cierre y retrospectiva.

## Artefactos mínimos por proyecto

- Resumen ejecutivo.
- Problema y objetivo.
- Usuarios y actores.
- Requisitos funcionales y no funcionales.
- Alcance incluido y excluido.
- Riesgos y restricciones.
- Decisiones de arquitectura.
- Roadmap o fases.
- Criterios de aceptación.
- Plan de pruebas.
- Guía de despliegue.
- Estado actual.
- Registro de decisiones.
- Lecciones aprendidas.

## Criterios de aceptación de la fase

- Existe una guía principal de metodología.
- Cada etapa tiene entradas, actividades, salidas y criterios de cierre.
- Se define cómo adaptar el proceso según el tamaño del proyecto.
- Se documentan roles y responsabilidades.
- Se establece el flujo Git oficial.
- Se incluye un mecanismo para registrar decisiones.
- Se incorpora un checklist de inicio y otro de cierre.
- El laboratorio web permite consultar visualmente la metodología.

## Fuera de alcance

Esta fase no implementará todavía las plantillas completas para Flutter, Firebase, APIs o GitHub. Esas plantillas se desarrollarán en una fase posterior usando esta metodología como base.
