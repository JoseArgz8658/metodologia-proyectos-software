# Fase 6 — Guías tecnológicas

## Objetivo

Traducir la metodología general del repositorio en criterios técnicos concretos para tecnologías habituales, sin convertir las guías en recetas rígidas ni sustituir las decisiones arquitectónicas.

## Alcance

- Selección de stack.
- Flutter y Dart.
- Firebase.
- Aplicaciones web.
- APIs REST.
- Persistencia local.
- Android móvil y Android TV.
- CI/CD con GitHub Actions.

## Principios

- El problema y las restricciones preceden a la tecnología.
- Las decisiones relevantes se registran mediante ADR.
- Las versiones y excepciones deben quedar documentadas.
- La seguridad y la operación forman parte del diseño.
- Cada guía exige evidencia verificable.

## Criterios de aceptación

- Existe una guía de selección tecnológica con matriz de evaluación.
- Cada tecnología cubierta incluye contexto de uso, reglas y validaciones.
- Las guías son compatibles con proyectos pequeños, estándar y críticos.
- No dependen de un proyecto concreto.
- Se mantiene trazabilidad con metodología, plantillas y ADR.
- La estructura puede ampliarse sin reorganizar el repositorio.

## Fuera de alcance

- Crear proyectos ejecutables completos.
- Fijar una única arquitectura obligatoria.
- Reemplazar documentación oficial de cada tecnología.
- Definir versiones actuales permanentes dentro de estas guías.
