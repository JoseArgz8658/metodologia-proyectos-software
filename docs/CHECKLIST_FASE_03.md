# Checklist de validación — Fase 3

## Metodología

- [ ] El ciclo completo se entiende sin depender de Flutter, Firebase u otra tecnología.
- [ ] Cada etapa tiene propósito, salida y puerta de control.
- [ ] Los artefactos mínimos cubren producto, arquitectura, ejecución, calidad y operación.
- [ ] Definition of Ready y Definition of Done son aplicables.
- [ ] La metodología puede reducirse o ampliarse según riesgo.
- [ ] Los roles representan responsabilidades claras.

## Git Flow

- [ ] `main` queda definido como rama estable.
- [ ] Las ramas temporales tienen convención consistente.
- [ ] Los commits siguen tipos comprensibles.
- [ ] El PR exige objetivo, alcance, pruebas y riesgos.
- [ ] Se prohíbe exponer secretos.

## Vista visual

- [ ] `metodologia.html` abre correctamente.
- [ ] El ciclo muestra las doce etapas.
- [ ] Los enlaces internos funcionan.
- [ ] El tema claro y oscuro funciona.
- [ ] La página es usable en móvil, escritorio y pantalla grande.
- [ ] La navegación por teclado conserva foco visible.

## Cierre

- [ ] No se modificó ningún otro repositorio.
- [ ] La rama parte desde la última versión de `main`.
- [ ] La documentación coincide con lo implementado.
- [ ] El PR puede revisarse sin contexto externo.
