# Roadmap general

## Fase 1 — Fundación

- Repositorio base.
- Laboratorio visual estático.
- Variables de diseño iniciales.
- Tema claro y oscuro.
- Publicación mediante GitHub Pages.

## Fase 2 — Design System

- Escala tipográfica.
- Paletas y roles semánticos de color.
- Espaciado, radios, bordes y elevación.
- Catálogo ampliado de componentes.
- Estados, accesibilidad y responsive.
- Reglas de adaptación hacia Flutter.

## Fase 3 — Metodología de proyectos

- Descubrimiento y definición del problema.
- Requerimientos funcionales y no funcionales.
- Alcance, riesgos y criterios de aceptación.
- Arquitectura y decisiones técnicas.
- Desarrollo incremental por fases.
- Pruebas, despliegue, mantenimiento y cierre.

## Fase 4 — Plantillas reutilizables

- README de proyecto.
- Plan de fases.
- Registro de decisiones técnicas.
- Pull requests e issues.
- Plan de pruebas.
- Changelog y release notes.
- Documentación de despliegue.

## Fase 5 — Guías tecnológicas

- Flutter y Dart.
- Firebase.
- Aplicaciones web.
- APIs REST.
- Persistencia local.
- Android móvil y Android TV.
- GitHub Actions y despliegue.

## Fase 6 — Casos de referencia

- Proyecto móvil.
- Proyecto web.
- Proyecto con Firebase.
- Proyecto multiplataforma.
- Ejemplos de decisiones, errores y lecciones aprendidas.

## Regla de avance

Una fase se considera terminada solamente cuando:

1. Cumple sus criterios de aceptación.
2. Tiene evidencia de prueba.
3. Su documentación está actualizada.
4. Fue revisada mediante pull request.
5. Se fusionó a `main` sin dejar trabajo crítico oculto.
